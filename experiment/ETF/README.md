# Reproducing the ETF Results

This folder contains the scripts used for the S&P 500 sector-index forecasting
experiment in the paper. The ETF paper tables and appendix diagnostics can be
reproduced after running the ETF experiment. The reproduce scripts read the
saved prediction files written by the training run and do not retrain models.

Run all commands below from the repository root:

```bash
cd <repo-root>
```

First run the ETF models, or point the reproduce scripts to an existing ETF
result directory containing one `model_*` directory per model and saved
forecasts such as `df_pred.csv`.

For reproducibility, we recommend explicitly passing the ETF result directory
to the reproduction scripts. The scripts can infer the latest matching result
directory automatically, but explicit paths avoid ambiguity when multiple runs
are present.

## 1. Recompute ETF Tables 3 and 4

The paper reports two forecast-to-position rules:

- `suffix1`: capped directional exposure scaled by a rolling maximum.
- `suffix2`: volatility-targeted exposure using a short rolling realized-volatility window.

Set the result directory produced by `run_scripts_ETF.py`:

```bash
ETF_RESULT_DIR="logs/ETF/<ETF_RUN>/<DATASET_NAME>"
```

If the separately supplied clean intermediary archive has been extracted into
`logs/`, use the saved paper forecasts directly:

```bash
ETF_RESULT_DIR="logs/ETF/reviewer_clean_results_package/etf_paper_results"
```

Then recompute the seed-level and seed-average metrics:

```bash
python experiment/ETF/reproduce_etf_tables.py \
  --selected-dir "$ETF_RESULT_DIR" \
  --output-dir "$ETF_RESULT_DIR"
```

If `--output-dir` is omitted, the output CSVs are written back to the selected
result directory.

This writes:

```text
suffix1_metrics_over_seeds.csv
suffix1_metrics_seed_average.csv
suffix2_metrics_over_seeds.csv
suffix2_metrics_seed_average.csv
```

`suffix1_metrics_seed_average.csv` corresponds to Table 3
(`table:ETF_performance_metrics1`). `suffix2_metrics_seed_average.csv`
corresponds to Table 4 (`table:ETF_performance_metrics2`). The reported paper
values are averages over 20 seeds.

## 2. Recompute Appendix ETF Figures and Table 9

The appendix subsection
`S&P 500 sector-index forecasting` reports:

- Figure 20: standardized predicted-versus-actual plots for Lasso and
  `PCA_NN_PCA_ADD`.
- Figure 21: prediction-binned calibration plots for Lasso and
  `PCA_NN_PCA_ADD`.
- Table 9: volatility-regime Diebold-Mariano signed t-statistics, using
  `PCA_NN_PCA_ADD` as the reference model.

To regenerate these artifacts from the same ETF run:

```bash
python experiment/ETF/reproduce_etf_diagnostics.py \
  --selected-dir "$ETF_RESULT_DIR" \
  --output-dir "experiment/ETF/diagnostic_outputs" \
  --seed 100
```

This writes the diagnostic PNGs and CSV files to:

```text
experiment/ETF/diagnostic_outputs
```

The main outputs are:

```text
ETF_pred_vs_actual_standardized_lasso.png
ETF_pred_vs_actual_standardized_pCA_NN_PCA_ADDOpt.png
ETF_bin_calibration_lasso.png
ETF_bin_calibration_pCA_NN_PCA_ADDOpt.png
ETF_dm_regimes_sp500.csv
ETF_dm_regimes_sp500_latex_rows.txt
```

For Table 9, the expected output schema is deliberately different from the
FRED DM table:

```text
reference model: PCA_NN_PCA_ADD
rows:            all, high_vol, low_vol
columns:         lasso, pls, arp, di, ewma, pcr
```

As a quick validation, the ETF table must contain `ewma` and must not contain
`FAST-NN` or `vanillaNN`. If either of those FRED-only model names appears, the
output from `reproduce_fred_diagnostics.py` has been used by mistake. With the
paper forecasts, `ETF_dm_regimes_sp500.csv` starts with the following `all`
row (rounded to three decimals):

```text
all,-0.769,-2.126,-2.206,-3.627,-0.889,-2.597
```

## 3. Optional: Re-run the ETF Models

The full ETF experiment can be rerun with:

```bash
python experiment/ETF/run_scripts_ETF.py
```

This script trains the ETF models listed in `model_l` over seeds
`100, 105, ..., 195`, using:

```text
train_window = 504
valid_window = 60
test_window  = 252
n_trials     = 20
start_test_date = 2017-08-01
```

The script writes a timestamped directory under:

```text
logs/ETF/
```

After a full rerun, the reproduce scripts automatically use the latest ETF
result directory under `logs/ETF/`. You can also pass that directory
explicitly via `--selected-dir`; this is the recommended approach for exact
replication.

The full rerun is substantially more expensive than recomputing the tables and
figures from saved predictions generated by the run script.
